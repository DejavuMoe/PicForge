# PicForge — Agent Guide

## Current state

Working version **0.19.0**, browser-only image toolbox. See the [documentation index](docs/README.md) and [architecture](docs/architecture.md). The package version does not establish a release/deployment.

- **Image compression:** existing `@jsquash/*` pipeline, batch resize, global/per-image settings, compare/zoom previews and ZIP manifest.
- **Android Motion Photos:** binary JPG + MP4 extraction; no re-encoding or Apple engine loading. Preserve the MotionFlow attribution.
- **iOS Live Photos:** Apple content-identifier pairing with basename fallback, HEIC → sRGB → baseline MozJPEG (browser HEIC decoder when qualified, otherwise libheif), MOV → H.264/AAC, clean-aperture crop/rotation, source timestamps or explicit 30 fps. The still and video convert concurrently. Video uses WebCodecs (runtime-selected decode/encode, frames rotated/cropped in YUV, own MOV/MP4 demux/mux) when the runtime supports the source, with PCM audio encoded by FFmpeg in parallel; otherwise, or on a non-cancellation WebCodecs failure, the original File converts with FFmpeg (read via WORKERFS). Serial jobs, cancellation/retry, individual downloads and ZIP.
- **Validation:** [current checks and limitations](docs/validation.md). Playwright WebKit does not establish real Safari/iPhone support.

## Code map

- `packages/app/src/App.tsx`: shared header, tool navigation, update prompt. `CompressionWorkspace.tsx`: compressor with active-tool clipboard import; `components/WorkbenchLayout.tsx`: shared queue/viewer/inspector layout. Default and legacy home entries open the Landing Page; users select a tool. Explicit tool URLs still open that tool; visited queues persist across home and browser history.
- `packages/app/src/motion/`: grouping/extraction/encoder arguments (`media.ts`), worker lifecycle (`processor.ts`), HEIF metadata (`heif.ts`), ICC/nclx → sRGB (`colorProfile.ts`), Apple identifiers, HEIC decode worker (browser decode checked against the clap/irot display size and limited to colour descriptions converted here; libheif fallback), separate JPEG encoder pool and QuickTime clean-aperture adapter. WebCodecs video: `movDemux.ts` (sample tables, signed ctts, edit lists), `videoFrames.ts` (FFmpeg-equivalent geometry, YUV rotate/crop, full→limited range), `mp4Mux.ts` (exact PTS, interleaved chunks, colr), `videoWorker.ts` and `webCodecsVideo.ts` (Worker lifecycle, capability/unsupported vs runtime fallback, session breaker). Both video paths must preserve frame count/PTS/geometry/colour semantics. Actual routing depends on the source and runtime capabilities; explicit 30 fps uses FFmpeg.
- Compression: Zustand `fileStore`/`settingsStore` → `useAutoCompress` → image router (animation first, otherwise Compat) → compatibility engine → `packages/codecs`. Compat decodes and resizes the original Blob inside its encode Worker (`workerDecode.ts`: createImageBitmap + OffscreenCanvas); the main-thread Canvas is only the fallback for a missing capability or a file the Worker cannot decode, never for cancellation, timeouts or limits, and always for SVG. Both paths use the same stepped downscale (`drawScaled`: `low` exact halvings, `high` final ≤2:1 draw) to preserve the same resize algorithm. Eligible opaque PNG-to-PNG without resize can instead use sanitized compressed bytes directly with OxiPNG. Per-image settings are complete snapshots. `advanced` is normalized to the active format's keys (`sanitizeAdvancedOptions`); presets replace format/quality/advanced and keep resize.
- Scheduling: `utils/resourceBudget.ts` is one page-wide memory budget for compression, animation and Live Photo jobs; the controller runs up to the encoder-pool size, selected file first. Reserve budget before entering the FFmpeg lane, never while holding it. Errors carry a class (input/settings/runtime/timeout): only runtime is auto-retried; settings and timeout errors requeue when settings change.
- UI: React 19 + Vite 8, token CSS in `packages/app/src/styles/` (tokens → base → controls → shell/workbench/preview/media) plus `landing/landing.css`, shared theme, i18next with five locales. Keep translation keys/interpolation aligned across all locales.
- All packages are ESM; internal dependencies use `workspace:*` and export TypeScript source. Tooling/TypeScript is shared from the root.

## Commands and checks

- Development supports Node `^22.13.0 || >=24.0.0` with pnpm 11.8.0. ESLint 10 retains the existing rule configuration; CI uses Node 24.21.0.

- `pnpm install`; `pnpm dev` (127.0.0.1:5173); `pnpm build`; `pnpm preview`. The approved HEIC module, WASM, license and manifest are versioned static inputs; ordinary builds and CI need no Emscripten or codec download. `pnpm test:heif` checks Git attributes and needs a checkout with `.git` (it cannot pass in a build mirror without it).
- HEIC uses source-built libheif 1.23.4 / libde265 1.1.1. `pnpm test:heif` verifies the asset gate; dev/build fail on absent, stale or mismatched artifacts. `pnpm codecs:heif` is only for deliberately regenerating/upgrading these assets ([instructions](docs/heif-build.md)). Do not restore the vulnerable libheif-js 1.23.2 package.
- Compression codec packages are exact-pinned to their static WASM. `static-codecs.mjs` verifies byte equality and maps upstream fallback URLs to `/wasm/` during production builds, including Workers. Keep this mapping and the AVIF/OxiPNG patches aligned when upgrading. `pnpm test:build` checks that contract and the existing performance-report validators; CI runs it without executing benchmarks.
- Required before release: `pnpm lint`, `pnpm test`, `pnpm typecheck`, `pnpm build`. Woodpecker CI runs these gates. Vitest uses Node; mock browser APIs when needed.
- CI uses one `.woodpecker/test-then-publish.yml` workflow: test/build/verify once, then publish that exact `dist/` from the shared workspace. Only the final step mounts `/deploy`; preserve master-push gating, failure propagation, production concurrency and the publisher's checksum/lock/atomic-switch checks. Do not reintroduce a second build before publishing.
- Media/PWA acceptance: `pnpm test:browser` (Playwright Chromium + native `ffprobe`). Select it when processing or shared runtime/asset/offline changes affect these paths; visual-only work does not require camera conversion. Artifacts default to a temporary directory. Override with `PICFORGE_BROWSER`, `PICFORGE_BROWSER_EXECUTABLE`, `PICFORGE_QA_OUTPUT`.
- Synthetic media smoke: `PICFORGE_SYNTHETIC_MEDIA=1 pnpm test:browser` requires native `heif-enc` with an HEVC encoder plugin (Debian: `libheif-plugin-x265`), `ffmpeg` (libx264/libx265) and `ffprobe`; all fixtures/exports stay temporary. The real-sample run also compares the HEIC export with an ImageMagick/LCMS sRGB conversion and checks video colour tags.
- Performance/codec regression: see [the harness guide](docs/performance/README.md). Preserve these reusable checks; keep one-off reproduction scripts, raw run JSON, traces and generated media temporary.
- UI changes: verify actual desktop/mobile behavior; use [QA checklist](docs/QA_CHECKLIST.md) and [implemented visual baseline](docs/UI_DESIGN.md). With the dev server running, `node scripts/ui-check.mjs` checks synthetic UI cases without HEIC/MOV conversion; `PICFORGE_UI_GROUPS=entry` checks Landing/footer/language/history; `layout,interaction` checks the workbenches. `pnpm format` applies Prettier.
- Shared control regression subsets: `details,ranges,usability` cover row insets, controls and numeric settings. `player` uses temporary portrait/landscape JPEG/MP4 fixtures via `PICFORGE_PLAYER_FIXTURES` to check both media tools, sub-second progress, scrubbing and hidden cleanup; see the [playback fixture contract](docs/QA_CHECKLIST.md#playback-fixture-contract).

- Camera acceptance uses the version-controlled, user-approved fixtures under `sample/` (see [fixture instructions](sample/README.md)) via `PICFORGE_SAMPLE_ANDROID`, `PICFORGE_SAMPLE_IOS_HEIC` and `PICFORGE_SAMPLE_IOS_MOV`. These files are test inputs only: preserve their original bytes and never copy them into application/public assets, precache or production output. Additional unapproved personal fixtures belong in ignored `sample/local/` or outside the repository. Expected frames/PTS/crop/rotation come from the current source; recent native ffprobe with Frame Cropping support and ImageMagick are needed for arbitrary camera fixtures.

## Minimum constraints

1. **Privacy and workspace hygiene.** The three existing fixtures listed in `sample/README.md` are explicitly approved by the user for version control. Do not commit any additional personal media without explicit authorization. Write exports/screenshots to temporary directories. Preserve unrelated working changes; do not commit, push or deploy without authorization.
2. **Everything stays local.** No uploads, telemetry or remote processing without product approval. Keep engines self-hosted and lazy; use bounded concurrency, worker cleanup and existing size/pixel guards. Prefer capability, initialization and qualification checks over UA sniffing; any temporary browser deny rule needs specific evidence, an issue/reference and a removal condition.
3. **Preserve media semantics.** Android exports must reconstruct original bytes. For iOS check main track, crop, rotation and per-frame PTS—not just nominal fps. The pinned FFmpeg needs the clean-aperture adapter; remove it only with a verified core upgrade. HEIC output is a web derivative converted to sRGB (matrix/TRC ICC or nclx; LUT-only RGB profiles are embedded instead), not an HDR/metadata-preserving archive. A browser HEIC decode must give the same result: accept it only at the exact display size and for colour descriptions this path converts; LUT, HDR and other descriptions stay on libheif. Identifiers are verified only when both halves contain them; basename-only pairs remain unverified.
4. **Preserve resize/settings behavior.** `contain` fits without upscaling; `cover` uses centered crop; `stretch` uses exact dimensions. Global edits must not overwrite per-image snapshots.
5. **Reproducible assets and offline behavior.** Dev/build run `packages/app/scripts/prepare-codecs.mjs`; codecs load from `/wasm/`. Keep `precache.json` generation and service-worker caching intact. Heavy engines work offline only after successful loading/caching; versioned engine directories are cached per engine version (`picforge-engine-*`), so update `ENGINES` in `sw.js` with an engine upgrade. A new service worker waits for the update prompt and keeps the previous app shell for one generation. Production HTML carries a CSP limiting connections and resource destinations to this origin, while leaving script-src unrestricted for WASM compatibility; new remote resources need an explicit, reviewed policy change. The user explicitly approved the four pinned files under `packages/app/public/wasm/heif-1.23.4-de265-1.1.1/` as versioned static assets; preserve their matching manifest and license. Other generated engine copies, `dist/`, `node_modules/` and `*.tsbuildinfo` remain untracked.
6. **Version and licenses.** Root/app versions must match; bump `CACHE_VERSION` in `packages/app/public/sw.js` when shipping a new version. Preserve notices under `packages/app/public/licenses/`: MIT app code does not relicense GPL FFmpeg/LGPL libheif. Satisfy codec source-distribution obligations before public binary distribution.
7. **Fallback and cancellation.** Keep the original Blob/File as the retry source; never fall back from a detached ArrayBuffer or pre-copy a full source buffer for fallback. AbortError, cancellation and stale task epochs must not trigger fallback, increment runtime failures, or publish results. Only explicitly classified infrastructure faults count toward the session breaker; corrupted/unsupported input does not. Bound retries and preserve one terminal outcome per task.
8. **Thread and memory ownership.** Compat Workers are created on demand, retired after large tasks and released when idle, because WASM heaps never shrink. The app is not cross-origin isolated (dev, preview and production alike); anything needing SharedArrayBuffer or pthreads requires a reviewed header change first. Preserve the AVIF/OxiPNG single-thread patches. Account for source and target pixels, resident engines and restart overlap; task completion or Worker target disappearance is not proof of immediate RSS/CPU recovery.

## Performance and documentation

- Prioritize measurable production-path performance, useful browser/runtime capabilities, and conversion/processing quality. Do not upgrade dependencies merely to chase newer versions. Keep documentation focused on current behavior, constraints and runnable checks; do not retain changelogs, phase reports, implementation progress or superseded concepts.
- Compare a candidate with current Compat on the same host, browser, input bytes and equivalent output settings. Record the actual path, fallback, latency, output size and quality. Keep raw measurements outside the documentation tree, labeled with source revision and environment; do not compute speedups across different hosts.
- A new engine or native path replaces Compat for a range only after performance and real application integration gates pass; initialization, correctness and an error circuit breaker do not detect successful-but-slow processing. Retain 60 MP as a safety-rejection case; do not bypass guards to obtain benchmark numbers.
- Preserve dimensions, crop/rotation, color/ICC, alpha and metadata-stripping behavior when optimizing. A faster or smaller output is not sufficient if quality or settings semantics changed. Remove buffer copies only after proving ownership, view bounds and lifetime. Do not conflate smaller explicit arrays with elimination of the browser's decoded bitmap.

## Validation proportional to the change

- During edits, run the directly affected checks. At a coherent implementation commit boundary, run lint/typecheck/unit/build once; documentation and concept-only changes need only appropriate content/diff checks.
- Keep fast unit tests and core Blob/cancellation/epoch/fault/thread regressions. Reduce repeated browser builds and broad matrix runs rather than deleting useful assertions. Reuse builds and select existing test subsets where supported; add only minimal filtering when missing.
- Match browser evidence to the change: geometry/options → affected cases; lifecycle/threads → cancellation/recovery; Vite/WASM/SW/headers → dev/production/304/offline; visual work → desktop/mobile, focus and relevant interactions. Repeat real Motion/Live Photo conversion only when its implementation, a relevant shared dependency/runtime, or release qualification warrants it.
- Preserve valid, unaffected prior evidence with its source revision. No unconditional retries, unrelated full-suite reruns, or benchmark collection alongside heavy tests. Expand coverage for an actual failure, unresolved risk, dependency change or default-engine/release decision.

## Unified visual design

- The current visual system is "darkroom ledger": [visual specification](docs/design/darkroom-ledger.md), [tokens](docs/design/design-tokens.json) (source: `packages/app/src/styles/tokens.css`) and [interface guide](docs/UI_DESIGN.md).
- Warm paper/ink chrome, one safelight-amber signal (`signal` fill with ink text; `signal-ink` for text on paper), IBM Plex Sans/Mono self-hosted (Latin subsets, OFL), 1 px rules, 2 px corners, no cards/shadows except overlays. Media is judged on the hue-free graphite stage in both themes (`.pf-stage-scope`); never tint, filter or draw over image pixels at fit zoom. Labels, registration marks and sizes sit in the mat. Figures are real values set in mono. No gradients, glass, glows, soft radii, emoji, particles or second accent.
- Branding uses the [folded P identity](docs/design/brand.md): ink body, amber play triangle; the ink tile is the header mark, favicon and app icon. The single SVG master is `packages/app/src/assets/logo.svg`; `pnpm assets:brand` (WSL: rsvg-convert, pango-view, ImageMagick, IBM Plex Sans OTF) regenerates `logo-tile.svg`, icons and sharing cards. Preserve ordinary/maskable icon roles, favicon revision URLs, exact social-image dimensions and the service-worker shell entries when changing assets.
- Home has a title sheet, three indexed tool links and a labelled generated sample comparison on the stage. On phones, tool entries precede the sample. The sample can be opened in the real compressor. No illustrative values may be presented as measurements.
- Preserve per-tool queues across home and browser history, global/per-image settings provenance, compare/zoom, cancellation, retry and downloads. Desktop uses queue/stage/inspector columns with the batch ledger under the queue; tablet shares the queue/stage column; phones use file-list/preview navigation in one scroll column with settings below and a sticky batch ledger. Format is a radio rail; presets are visible recipes; the view bar has one switch for original/result/split/two-up.
- Keep home row columns aligned with a shared template and symmetric insets (20 px desktop/tablet, 12 px mobile), reserve stable scrollbar gutters, and give shared controls explicit hover/focus/disabled styles. Range/number pairs share heights even when disabled. The language picker contains only the five language names. Browser detection is the initial default, never a displayed option or policy label.
- Use the shared themed combobox (for non-format choices), including its popup, and styled dialogs. All web control states, hints and video playback controls use application styling; pointer clicks do not leave keyboard focus frames. Number fields accept temporary drafts, apply on blur/Enter and cancel with Escape, retaining focus on Enter/Escape. Preview controls stay outside the image and remain available in fullscreen. PNG clearly identifies its lossless behavior.
- In both media tools, the playback dock matches the visible video's left/right edges and directly follows its bottom edge. Never stretch it to the enclosing pane. Narrow players move the timer to a separate row; resizing and tool reactivation must recompute the fitted size. A video whose metadata loads without a frame size (undecodable track, e.g. HEVC) uses the still-image fallback.
- Photos have their own fitted strip with actual output pixel dimensions and fullscreen access. Match the paired dock height on desktop, keep download rows aligned, and retain a compact strip on mobile. Do not fill the photo side with decorative playback controls.
- Keep all five locales aligned. Browser language is the default with English fallback; persist only explicit choices under `picforge.language`. URL previews and the legacy detector cache must not override automatic detection. Theme follows the system until explicitly chosen; unavailable storage must not break rendering.
- GitHub is an icon link at the top right. Every normal page shares a status-line footer: copyright left, local-processing/version centre and Riven Cloud right on desktop; copyright above sponsorship, both centered, on mobile. Do not restore About or a raw license link to the primary footer. Preserve all license files and attribution, including removed historical components.
- Keep screenshots, generated exports and unapproved personal samples temporary; the approved originals in `sample/` are permanent test fixtures. The committed dune assets are generated, non-personal examples; attribution and generation/encoding details are in the design brief. Keep generated asset provenance distinct from implemented capabilities and measurements.
