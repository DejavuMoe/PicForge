# Phase 4 后的可行性评估与推进计划

日期：2026-09-08。评估基于 `cabbf12`，本文件是后续方案，尚未实施或提交。

用户随后明确了性能、技术栈能力、转换/处理效果三项工程重点，并要求先设计统一视觉。
必要约束已提取到 AGENTS.md；视觉提案见 [影像工作台](design/visual-direction.md)。
视觉实现与处理管线优化分开推进，避免同时修改样式和算法导致验收范围失控。

参考：[分享的技术分析与原始计划](https://chatgpt.com/share/6aa02505-0b0c-83ea-8b6d-b1ae0b5f83ae)。
可见分享内容包含最初的技术分析和 v0.1 实施计划，没有针对当前 Phase 4 提交的新增审计。
以本地代码和阶段验证报告为当前事实，不重做已完成阶段，不覆盖历史性能基线。

## 判断

- 保留已经实现的 Vips 引擎、原始 Blob 回退、故障分类及取消保护。
- 默认引擎选择仍需数据；不得将功能矩阵通过等同于性能验证。
- 现有熔断针对运行失败，不能识别“成功但非常慢”；默认策略仍需性能资格验证，不能只依靠 capability 和 breaker。
- 下一阶段应优先改善实际生产路径。当前生产仅注册 Compat，仍先展开原尺寸 RGBA，再 resize、复制和编码。
- 原计划 Phase 5 的 Vips 专用 Worker、串行通道、强制取消，以及一部分 Phase 7/8 的按需加载、离线和兼容验证已在 Phase 4 完成，不重新建设。
- 减少重复构建和重复浏览器运行，保留能捕获真实语义回归的测试。

## 对参考意见的修正

1. 依赖版本表描述的是旧 master；Phase 1 的升级已经完成，不启动第二轮“追最新”。
2. 直接绘制到目标 Canvas 可以避免原尺寸的显式 RGBA 回读和中间复制，但不能保证浏览器不分配完整解码位图。内存收益须区分数组减少与实际进程峰值。
3. Worker 中的 createImageBitmap / OffscreenCanvas 具有可行性，但仍需验证方向、ICC、alpha 和失败回退。Canvas 的浏览器实现差异不能仅凭 API 存在就排除。
4. postMessage transfer 本身已经正确；应检查 transfer 前后的 slice、typed-array 和 ImageData 复制，并先证明所有权，再删除复制。
5. 当前 AVIF/OxiPNG 单线程补丁修复了隔离头下的 glue/WASM 不匹配。现在不移除补丁，也不顺便启用 OxiPNG 多线程。
6. 内存预算不能只按目标像素计算：缩略图任务仍可能解码巨大源图，还存在 WASM 常驻堆、编码临时空间和重建重叠。
7. Safari 上游性能问题是外部报告，不能视为当前实现的实测结论；Playwright WebKit 也不能替代真实 Safari 资格验证。

## 建议执行顺序

### 5A：精简验证入口，补一轮小规模同机对比

先增加可选择的 smoke / semantics / lifecycle / offline / dev 子集，支持浏览器和场景过滤。
尽量复用一次临时构建；只在测冷启动时重建运行环境，不为每条断言重建整个站点。
这一步先做够用的参数化，不建设新的通用测试平台，也不批量重写现有断言。
旧 probe 保留为资产/初始化诊断入口，不再默认与正式引擎完整验证串联重复运行。

在当前 Mac 上比较当前 Compat 与现有 Vips，固定同一输入字节、浏览器、设置和隔离条件。
初筛仅 Chromium，使用六个场景：

- JPEG 12 MP → JPEG，原尺寸。
- JPEG 24 MP → JPEG，长边 1920。
- JPEG 48 MP → JPEG，长边 1920。
- JPEG 24 MP → WebP，长边 1920。
- PNG alpha → WebP，缩小。
- 五张照片混合批次，比较实际通道并发，不只串行单图。

每个单图场景一次明确标注的首次任务、三次 warm 样本；噪声影响决策时才增加重复。
记录端到端耗时、首个结果、输出尺寸/字节、实际执行引擎、fallback、Long Tasks 和重建次数。
先保证输出语义及合理画质可比。不可把 Vips 自动回退后的 Compat 耗时标记为 Vips 成绩。
首次任务须说明 HTTP/编译缓存条件；性能采集不与其他重型测试并行运行。

旧基线来自 Linux/Intel，不能直接与本机 Mac 数字计算提升比例。
新结果写入独立文件，保留版本、环境、fixture 哈希和原始样本。
60 MP 继续作为安全拒绝用例，不绕过 50 MP guard 来制造性能结果。

交付：精简的运行入口、同机对照报告、下一步优先级。此时不启用生产 Vips。

### 5B：融合 Compat 解码与目标尺寸绘制

保留现有 ImageEngine 契约、编码器和设置快照，复用 calculateResizeGeometry。
让解码后的图像直接绘制到目标 Canvas，只回读目标尺寸像素；不先生成完整源 RGBA 再 putImageData。
逐处确认独占缓冲区和 byteOffset/byteLength，才消除可安全删除的复制。
ImageBitmap/Canvas 资源在 finally 中释放。

这一步优先带来当前生产路径收益。先实现一个受控的小改动，不同时重写调度器、加入新存储层或更换编码器。
若改变了渲染路径，不再以“新旧压缩字节完全一致”为唯一标准：尺寸/裁切/方向必须严格正确，颜色与 alpha 复用现有语义断言；变化须有明确原因。
旧实现可保留为开发对照，但不增加普通用户的复杂引擎选项。

交付：独立优化提交；用同一六场景重新对照，并验证未改变参数和取消语义。

### 5C：根据测量补齐 Worker 与资源调度

若融合后 Compat 的解码/绘制仍造成明显主线程阻塞，将该路径移到已有编码 Worker 的任务中：
Blob → createImageBitmap → OffscreenCanvas → jSquash。
按功能与操作成功与否选择路径，不按浏览器名字判断；不支持的输入或平台仍可使用原有兼容路径。
先覆盖普通 JPEG/PNG/WebP，不强行扩大到 SVG、动画等输入。

Vips 已有专用 Worker，直接复用。不要再实现一套 Vips WorkerPool。
preflight 仍存在于应用控制器；若测量证明重复读取/解码开销显著，再缓存不可变源的已验证尺寸或补常见格式头部读取，不能删除尺寸安全检查。

资源调度先用保守的源像素、目标像素及格式成本控制大图并发。
计入引擎固定成本和取消/重建余量；仅估算目标 RGBA 会低估大源图。
保留 AVIF=1、OxiPNG≤2 和 Vips 活跃任务=1；暂时保留六 pthread 的已验证配置。
不先追求精确 RAM 探测或动态调参。只有实测显示六线程常驻成本成为瓶颈，才单独比较同步降低两个内部池限制。

重点验证混合引擎、连续取消/重试、排队时熔断生效范围，以及取消后立即开始下一任务的资源重叠。
区分任务 Promise 已结束、旧 Worker 目标已消失和实际 CPU/RSS 回落。

交付按 Worker 改动和调度改动分别提交；超时参数根据观测校准，不直接把 90 秒资格测试 watchdog 作为生产结论。

### 6：选择默认范围，再做真实应用集成

比较优化后的 Compat 与 Vips，不能只让 Vips 与未优化的旧路径竞争。
扩展到 Firefox/WebKit 的代表性场景；真实 Safari 结果单独记录。
确认有稳定收益后，才增加应用内部 opt-in 接入，验证 controller、全局/单图设置、取消、回退、下载和离线完整路径。
临时验证页通过，不代表真实应用接入已通过。

只有满足语义、质量/体积、耗时/响应性和资源边界要求的范围才能进入 Auto 默认策略。
收益含糊或严重变慢的范围继续 Compat；不因已经实现 Vips 就必须启用它。
默认策略调整前跑一次完整相关浏览器矩阵与批量压力场景，20/50 文件的大矩阵留在这里。

## 测试执行规则

| 改动 | 日常验证 | 扩大验证的触发条件 |
| --- | --- | --- |
| 文档、注释、纯配置说明 | diff/引用检查 | 不运行媒体转换 |
| 纯参数映射、几何 | 对应单元测试 | 影响真实编码/渲染时补相关浏览器案例 |
| Compat 融合/搬入 Worker | 调度竞态测试 + Chromium 小型语义集 | 合并前一次三浏览器方向/ICC/alpha/格式验证 |
| Vips 生命周期、内部线程补丁 | lifecycle 子集 + targeted real WASM | 单独补必要的大图取消与线程清理；不叠加完整颜色矩阵 |
| Vite、WASM URL、SW、隔离头 | build + dev/production/304/无隔离/离线子集 | 共享基础设施影响全部工具时补合成媒体验收 |
| Motion/Live Photo/HEIC/FFmpeg | 对应媒体测试 | 改动触及其实现或共享基础设施才重跑真实样本 |
| 默认引擎范围、依赖/编码器升级、发布候选 | 完整相关矩阵 | 真实 Safari 和必要的真实媒体验证 |

保留快速的 174 项单元测试；最近一次全套执行不足一秒，主要成本不在这里。
每个独立实现提交结束时跑一次 lint/typecheck/unit/build；小步编辑时仅跑直接相关检查。
不要在修复一个用例后从全套第一项重新跑起，也不要用无条件重试掩盖失败。
已通过且未受影响的证据继续有效，报告注明来源提交和本次覆盖范围。
原始 Blob、AbortError 不回退、epoch 失效、故障分类及线程边界属于不可删除的核心保护。

## 暂缓

预览/导出双管线、Streaming ZIP、OPFS、新格式、额外依赖升级、OxiPNG 多线程和降低 Vips pthread 数量均不进入下一笔改动。
只有指标说明它们成为主要瓶颈或用户提出明确需求，才单独立项。
继续遵守本地处理、个人样本不提交、不 push/部署/发布的约束。
