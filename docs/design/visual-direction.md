# PicForge 统一视觉：影像工作台

状态：工作台信息结构基准。2026-09-09 的后续视觉审阅已更新入口、玻璃材质、粒子与动效要求；这些部分以 [interaction-redesign.md](interaction-redesign.md) 为准。
性能、技术能力和处理效果的优化仍按独立改动推进；本次仅迁移视觉、入口和界面交互。

## 设计判断

旧首页的大号宣传标题、蓝紫光晕、粒子背景、重复工具入口和功能说明，比实际处理动作更抢眼。
工作区则把工具标题、导入容器、工具栏、结果和设置做成多套局部结构，缺少稳定的视觉层级。
新方向以图片和处理任务为中心，通过布局、文字、对齐和状态呈现建立识别度。

设计关键词：中性、精确、连续、可操作。品牌仍是 PicForge。
不增加云功能、AI 修图、滤镜、直方图、曝光面板、账户或虚构效率指标。

## 页面结构

### 桌面

- 一条稳定的顶栏：PicForge、三个工具、语言和主题。源码/许可等次要入口保留，但降低视觉权重。
- 内容区由文件列表、主预览和检查器组成。它们是连续区域，不在每一块外面套圆角卡片。
- 文件区以缩略图和文件名为主；格式、大小、状态为次级信息。选中态使用浅底色和细标记，不让每个文件变成按钮卡片。
- 预览区在可用空间内尽可能大。照片保留原比例，默认 contain，不为版式好看裁掉内容。对比两侧必须是同一图像、同一缩放和视口。
- 检查器只显示当前工具真实可操作的参数。不同工具共享标签、输入、下拉、开关和分组的样式，不共享不适用的参数。
- 底部固定操作条处理全局状态与批量操作。局部文件下载使用较轻的文本/次级按钮，与批量导出区分。

初始布局目标：顶栏 56px、底部操作条 56–64px，文件栏 224–256px，检查器 280–304px，中间区域 flex。
窗口变窄时先收起辅助区域，而不是挤压预览与控件。1536px 概念图用作构图参考，具体响应式尺寸以规范和实际内容校验为准。

### 首次进入 / 空态

最新用户决定：默认入口恢复为独立 Landing Page，让用户先选择工具，再进入工作台。
首页仅保留简短标题、说明、三条工具入口和底部项目信息；不恢复旧营销页的粒子与功能卡片堆叠。
默认路径和 `tool=home` 打开首页；显式工具链接直达工作区。品牌返回首页，浏览器前进/后退与工具切换保留已访问队列。
详细的克制液态玻璃材质范围与验收见 [interaction-redesign.md](interaction-redesign.md)。

工作区空态仍保留主结构和真实导入入口；没有选中文件时“仅此图片”禁用，没有结果时导出禁用。

### 图片压缩

- 检查器顺序：设置作用范围 → 输出格式 → 质量 → 尺寸与缩放方式 → 高级设置。
- “全部图片 / 仅此图片”必须反映真实设置来源。全局值和单图完整快照继续按现有语义工作；取消单图覆盖需要明确入口。
- contain 的字段文案为“最大宽度 / 最大高度”，cover/stretch 为目标尺寸，避免把边界尺寸误写成保证输出尺寸。
- 原图 / 结果 / 对比放在预览工具栏；缩放及适应窗口位于预览边缘的固定位置。
- 当前引擎仍自动处理，不添加虚假的“开始压缩”手动步骤。参数变化使旧结果失效时，界面必须明确处于重新处理状态。
- 不支持的高级参数由现有策略处理；普通界面不显示 Vips、SAB 或内部回退术语。

### Android 动态照片

- 文件列表仍是普通文件行，状态为待提取、处理中、完成、失败或已取消。
- 主区使用照片/视频配对预览，与 iOS 的结果容器和播放控件一致。
- 右侧是**输出信息**：原始 JPG、原始 MP4、实际大小和各自下载动作。
- 明确说明“保留原始字节，不重新编码”。不显示质量滑块、缩放、帧率或编码预设。
- 首次操作为“提取文件”；结果存在后，批量主操作转为导出。错误和重试留在对应文件旁边。

### iOS 实况照片

- 队列按配对分组。同名 HEIC+MOV 在一行中，缺失文件用文字说明“缺少 MOV/HEIC”，不只靠颜色。
- 主区显示 JPG 与 MP4；视频提供真实播放、暂停、进度和全屏，不伪装为完整视频编辑器。
- 右侧顺序：画质预设、源时间戳/30 fps、照片质量、保留音频。参数作用于当前批次，不复制图片压缩的单图作用域开关。
- 缺少配对、处理锁定和重试状态沿用现有业务规则。配对说明仅在有帮助的状态出现，不永久占据主预览上方。
- 保留原始主轨、clean aperture、方向与 PTS 的技术约束；不宣称归档级 HDR/元数据保留。

### 手机

- 顶部保留品牌、当前工具选择器和次要菜单；完整工具名在菜单中可读，不将三段长中文挤成窄列。
- 队列、预览、设置使用分步视图/可展开区域。返回队列保留选择和当前任务。
- 预览维持合理显示面积，设置进入单列；宽/高这类强关联短字段可以双列。
- 主操作在底部，预留 safe-area 和足够内容内边距；键盘、设置面板不能遮挡关键操作。
- 触控目标至少 44×44px，不能以缩小字号来容纳桌面控件。质量滑块同时提供可精确编辑的值。

## 视觉令牌

| 语义                 | 浅色      | 深色      |
| -------------------- | --------- | --------- |
| app/chrome           | `#FFFFFF` | `#202222` |
| auxiliary surface    | `#F6F6F6` | `#242626` |
| image mat            | `#E8E8E8` | `#161818` |
| text primary         | `#202322` | `#ECEEEC` |
| text secondary       | `#616762` | `#ABB0AC` |
| separator            | `#DDDFDD` | `#373B38` |
| control border       | `#858C87` | `#747D76` |
| accent               | `#245946` | `#91BBA4` |
| selection background | `#EDF3F0` | `#303E37` |

- 界面大面使用纯色；照片周围维持中性，不能叠加彩色渐变、磨砂或光晕干扰判断。
- 强调色用于主操作、焦点与必要的选中提示。作用域、预览模式等次级切换优先浅底/文字/下划线，避免所有选中项都画成强按钮。
- 成功/等待/错误使用语义色加文字；不把百分比减少、完成数量做成夸张绿色营销标签。
- 圆角：媒体 0，常规控件 4–6px，弹出菜单 8px。阴影仅用于覆盖层；固定三栏没有浮起阴影。
- 间距：4/8/12/16/24/32；分组依靠空白，一级区域才用分隔线。避免重复边框。
- 字体优先系统 sans：system-ui / -apple-system / Segoe UI / PingFang SC / Microsoft YaHei；不运行时请求远程字体。
- 桌面控件/正文 14px，次要元数据 12–13px，分组标题 15–16px，工作区/空态标题 22–24px。中文不使用过紧字距。数字尺寸、大小和进度用 tabular-nums。
- 图标沿用现有 Feather 风格：16–18px、统一描边、光学居中。图标按钮有可访问名称，不增加装饰性图标底板。
- 动效仅限 120–180ms 的颜色/显隐过渡，不使用缩放弹跳、悬停位移、持续背景动画；遵循 reduced-motion。

颜色、禁用态和 focus ring 在实现时逐项验证可读性，正文至少 4.5:1，关键非文本控件至少 3:1。
不能根据生成图的抗锯齿或细微噪点给界面添加纹理。

## 组件与状态契约

复用 AppShell、ToolNavigation、FileRow/PairRow、MediaViewer、InspectorSection、Field/Select/Switch、TaskStatus 和 ExportBar。
三种工具使用这些组件的明确变体；不复制三套 CSS，不更换 React/Vite/Zustand，也不为视觉增加大型 UI 依赖。

| 状态       | 必须表达                                         |
| ---------- | ------------------------------------------------ |
| 空         | 真实可操作的导入入口；没有伪造文件或进度         |
| 排队/处理  | 任务状态、可取消动作；不编造编码百分比           |
| 完成       | 最新设置对应的可导出结果和真实大小               |
| 过期       | 旧预览明确标识或切回原图；旧结果不能误导为可导出 |
| 失败       | 对应文件的简短原因与有边界的重试                 |
| 已取消     | 不显示完成；可以按现有语义重新处理               |
| 配对缺失   | 缺少哪一个文件，允许补充输入                     |
| 播放不支持 | 静态预览和可用下载，不让结果区域空白             |

保留五种语言、键盘导航、菜单/下拉的 focus 管理及主题切换。重要动作不能依赖 hover 才发现。
原版作者、源码、许可证和赞助入口应保留在合适的次级位置。

## 实施边界

1. 先确定这一视觉方向及入口调整。
2. 单独实现 tokens/字体/导航/连续布局，复用现有处理逻辑；再逐工具迁移队列、预览、检查器和状态。
3. 视觉验收限于实际桌面/手机、五语言关键文案、焦点/键盘、设置作用域和下载入口；单纯样式改动不重跑真实 HEIC/MOV 转换。
4. 性能、Worker、编码或转换效果的改动另行实现与提交，以其专属证据验证，避免视觉与算法同时变化而无法归因。
5. 没有同条件性能数据前不扩大 Vips 默认范围，不通过减少质量或弱化媒体语义来制造“更快”。
